## 1. 必改项（做完才算收尾）

1) v2 统计层不达标（最重要）
   - 现状：v2.yaml 只有 scenario_count=8 天、r_list=[0.4,0.7,0.9]、lot_types=[plc]；v2 只输出点估计（v2_best.csv、v2_designs.csv、v2_service_accounting.csv），没有 v2 的置信集合、g(r) 曲线、三区判定、CVaR。现有 confidence_sets.csv / g_curve.csv / cvar.csv 只覆盖静态层。
   - 改法：v2 scenario_count → ≥300 天（日块）；r_list → 0.2–1.0 步长 0.1，并在 g(r) 变号附近加密到 0.02；lot_types 至少 [pnc, plc]。
   - 要求 v2 输出同口径的：g(r) 与置信区间、候选置信集合（block bootstrap + max-t/holm，块长=1 天）、三区标签（full_dominant / partial_dominant / undetermined）、CVaR_0.95（含 tail_samples 与 aux 变量两条值）。文件名沿用现有命名，加 v2_ 前缀。
   - 若因算力缩减场景，必须在报告与 README 里明写"v2 统计结论不可用于推断"，不能静默用 8 天出置信集。当前耗时 7 s，300 天预计 3–5 分钟，可接受；用同一批轨迹复用给所有 (m,π) 控成本。

2) 图 8 的稀缺度轴缺失
   - 现状：报告已承认"三区域图缺少稀缺度横轴网格，只给 Pnc/Plc 两个场地"。
   - 改法：用 vacancy/leaving rate 生成 (r, 稀缺度) 网格，输出 fig8_regions.csv（r、scarcity、g_hat、g_lo、g_hi、region），供后续画三区图；不要求画图。

3) 输出目录卫生与 canonical run
   - 现状：outputs/baseline/ 下 16 个时间戳目录（早期半成品也在），没有"哪个是正式结果"的标记；仓库根、src、tests 下都有 __pycache__。
   - 改法：保留一个 canonical 产物（如 outputs/baseline/canonical-seed42/，内容为最终一次完整运行），其余移入 outputs/_archive/ 或删除；README 与报告只引用 canonical 路径；新增 repro/.gitignore（outputs/、__pycache__/、*.pyc），说明 outputs 是可重算生成物。

4) cvar.csv 的 cvar_full_install_rmb 含义不明
   - 现状：36 行里部分行为 0（如 pnc/beta 全部为 0），其余约 9–12.9M。0 是"未计算"还是"零成本"无法区分。
   - 改法：未计算的写 NaN 并加 full_install_evaluated 布尔列；或者实现全安装 CVaR 并在报告中说明零值原因。两种都可以，但不能留歧义。

5) README 的图号映射与 v2 稿不一致
   - 现状：README 把 v2_timeline_sample.csv 标成"v2 图 9/图 10"，v2 稿里实际占位是 Fig. 6/7/8 与 Table 9/10/11（见 docs/reports/新论文扩写方案_2026-10-29.md 第 5 节）。
   - 改法：逐行对照改成 Fig. 6（时间轴）/ Fig. 7（g(r)）/ Fig. 8（三区）/ Table 9（规则矩阵）/ Table 10（资源台账）/ Table 11（可靠性表）。
