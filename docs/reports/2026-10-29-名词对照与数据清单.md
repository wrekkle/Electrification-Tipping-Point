## 一页话术（跟学姐/上级讲，三句话）

1. 我们担心的不是模型不会算，而是"**EV 里到底有多少比例是来充电的（q）**"这个参数没人测过，拿它当已知，结论就站不住。
2. 所以用两招把它夹住：**B 招只看总账**（这个场一共被占了多少车时、充电桩一共充了多少次），用这两个数就能算出 q 的范围，不需要任何分布假设；**C 招再建一个模拟器**，输入参数吐出占用曲线，拿真实曲线去反推 q，但它依赖假设。
3. 两招对得上（后验大部分落在 B 的区间里），才敢报结论；对不上就只报 B 的区间。最后把 q 的不确定性带进拐点，**拐点就从"0.7"变成"[0.6, 0.8]"**。

## 第一页：名词对照

| 名词 | 人话 | 打个比方 | 要不要背 |
|---|---|---|---|
| q（充电需求率） | EV 到达里真正插枪充电的比例 | 来 100 辆电车，几辆会充电 | 要 |
| 部分识别 / 界（B 招） | 不猜分布，只用总账把参数夹在一个范围里 | 不知道每人饭量，但知道总饭量和人数范围，就能算人均饭量范围 | 要 |
| 反演（C 招） | 从看得见的结果倒推看不见的原因 | 看一天的空位曲线，倒推多少车来、停多久、几辆来充电 | 要 |
| 生成模型 | 一个能"演戏"的模拟器：给参数，它就演出一段占用曲线 | 沙盘推演 | 要 |
| 先验 / 后验 | 看数据之前你认为 q 大概多少 / 看完数据后更新成多少 | 出门前估天气 / 看了云再估 | 知道即可 |
| ABC（近似贝叶斯计算） | 精确概率算不出来，就用"模拟很多次 + 比谁更像"来凑 | 猜重量：做一堆同重量模型，挑和实物最像的 | 知道即可 |
| SBC | 用"已知答案"的假数据检验方法靠不靠谱 | 拿标准答案考自己 | 知道即可 |
| 可识别性 | 数据里到底有没有足够信息把参数定住 | 只看平均分，看不出谁偏科 | 要 |
| 摘要统计 | 把一天的曲线压缩成几个数再比较 | 用平均分、最高分概括一个班 | 知道即可 |
| 置信集 / 可信区间 | "不能排除"的答案集合 / 参数的合理范围 | 不是给一个数，是给一个范围 | 要 |
| ETP（拐点） | EV 比例过某个值后，全装桩突然比部分装更划算 | 临界点 | 要 |
| 占位不充电 | 车停在充电位上但没插枪，等于白占一个充电位 | 停在加油站不加油 | 要 |
| 浪费率 | 充电位被"不充电的车"占掉的时间比例 | 车位空转率 | 要 |
| d_min / d_max | 一辆车停留时长的合理上下限（比如 15 分钟到 8 小时） | 最短停多久、最长停多久 | 要（找数据时要问） |
| 共同随机数 | 所有方案用同一批随机事件，差异才来自方案本身 | 同一张考卷比成绩 | 知道即可 |
| 双区间 | 识别区间（数据撑得住的）+ 后验区间（模型给的），取交集 | 两个圈的交集 | 要 |

## 第二页：要收集的数据

### 必需（没有就做不出主线，B 和 C 都废）

| # | 数据 | 字段 | 粒度/跨度 | 用来干什么 |
|---|---|---|---|---|
| 1 | 停车占用快照 | 场地 ID、时间戳、总车位数、空位数 | ≤10 分钟，≥3 个月 | 算占用车时，B 的输入 |
| 2 | 充电会话明细 | 桩号、场地 ID、开始/结束时间、交付电量 kWh、功率、结束原因（正常/拔枪/故障） | 精确到分钟，≥3 个月 | 算充电次数 n_s、平均单次电量，B 的输入；C 的真值校准 |
| 3 | 充电桩状态位 | 每个桩每个时刻：空闲/占用未充/充电中/故障 | ≤10 分钟 | 区分"停着不充"，算浪费率；C 的 S_t |
| 4 | 场站容量 | 变压器/馈线容量 kW、桩额定功率、桩数、车位与桩的对应关系（哪几个车位共用一根桩） | 静态 | A7 容量能量约束 |
| 5 | 场地属性 | 车位数、充电位数、类型（公共/配建/路侧）、坐标、周边用地 | 静态 | 区分稀缺度，做两场地对比 |

### 加分（有就更好，没有也能做）

| # | 数据 | 用来干什么 |
|---|---|---|
| 6 | 车牌级进出记录（脱敏哈希即可） | 估 EV 比例 r、停留时长分布、重复到访；B 的 r 更准 |
| 7 | 价格：停车费、充电服务费、峰谷电价 | A11 分配与支付分析、运营者视角对比 |

### 找数据时要问清的 8 件事（照抄去问）

1. 快照的采样间隔是多少分钟？有没有缺测？缺测怎么补？
2. 充电桩的"故障/离线"怎么标记？会不会被当成"空闲"？
3. 充电会话里"结束原因"分几类？拔枪未充满算不算一次会话？
4. 车位和桩是不是一一对应？一根桩能不能管两个位？
5. 场站总功率上限（变压器容量）是多少？有没有需量电费？
6. 数据时间跨度能不能给到 3–6 个月，含工作日/周末/节假日？
7. 能不能给字段字典 + 3 行样例 + 脱敏说明 + 使用授权（影响论文 Data availability 怎么写）？
8. 能不能给 3–5 个不同稀缺度的场（很满/一般/很空），最好同一城市同一运营商？

### 拿不到时的降级路径

| 情况 | 还能做什么 | 论文怎么写 |
|---|---|---|
| 有会话、没有状态位 | B 照做；C 用会话校准 | 正常写 |
| 有状态位、没有会话 | B 的界变宽（n_s 用状态变化数近似）；C 可做但弱 | 报区间，写数据限制 |
| 只有占用快照 | 只做 B（用 d_min/d_max 给宽界），C 大概率不可识别 | 结论只写"界内稳健"，把不可识别写成局限 |
| 全都没有 | 用公开 ACN-Data 做方法验证，本地只做情景 | 明写"外部校准，非本地结论" |

## 补充：五项数据必须来自同一个停车场吗？

**必须同场、同时段、能靠键对上，但不需要把五项全部重新收集。** 关键不是"重采"，而是找到一个"两边都有"的场。

| 项 | 现在从哪来 | 能否沿用 |
|---|---|---|
| 1 占用快照 | 聚美/腾讯云平台（已有 638 个场） | 能。只要挑出运营方也有数据的那个场 |
| 5 场地属性 | 同平台/地图 | 能，静态数据 |
| 2 充电会话 | 场站运营方或充电运营商后台 | 要新要 |
| 3 桩状态位 | 同上 | 要新要 |
| 4 场站容量/功率 | 运营方工程资料 | 要新要 |

如果运营方同时有道闸/车位引导系统（很多商业停车场有），第 1 项也能从他们那拿，**单源最省事**，还免去口径对不齐。

**最小可行数据集**：1 个场 × 3 个月 × 五项齐全，就能做 MVE；主线 3–5 个场。不用一上来要 638 个场。

**对齐时要确认的键和口径**：

- 键：场地 ID、时间戳、桩号 → 车位映射；
- 时区与夏令时；
- "空位"定义：含不含充电位？故障/离线桩算不算占用？
- 车位数以运营方工程资料为准（两个来源经常差几个）；
- 快照粒度与会话粒度不同，按时间戳对齐即可，不要强行插值。

**三种"对不上"的情况与对策**：

| 情况 | 能做什么 | 论文怎么写 |
|---|---|---|
| 同场同期（理想） | B 和 C 联合识别，主线 | 正常写 |
| 同场不同期 | 用同期数据做 B/C，另一期做外部验证 | 写 external validation，不写联合识别 |
| 不同场 | 分场报告 q，做外部有效性检验 | 写"场间异质性"，不做联合识别 |
| 只有一边 | B 的宽界 + 情景 | 写数据不足、不可识别 |

**行动顺序**：先列平台已覆盖的场 → 找运营方要他们的场列表 → 按名称/坐标（200 米内）匹配 → 锁定 1–3 个场 → 要同场同期至少 3 个月的五项数据。


## 补充：公开打包数据集（2026-10-29 检索）

结论：**有免费打包数据集，但没有一个"同一个场、既有普通车位占用又有充电桩状态"的**。最接近的是"充电站级占用+电量"和"充电会话明细"两类，正好够做方法验证。

| 数据集 | 地点/规模 | 时间与粒度 | 含什么 | 能否替代本地数据 |
|---|---|---|---|---|
| UrbanEV（Dryad，免费，约 320MB） | 深圳，2 万+ 充电站 | 6 个月，**小时级** | 充电占用、时长、电量、价格 + 天气、空间信息 | **最接近中国场景**；能做"占用高但电量低 = 占位不充电"的 B 界演示，但不能替代车位分钟级数据 |
| 4TU "EV Charging Session Data of Large Office Parking Lot"（CC BY-NC-SA，CSV） | 荷兰 Utrecht 办公楼停车场，约 300 个充电点 | 2020-08 至 2024-10，**会话级** | 充电会话（到达、离开、电量） | **做 C 的闭环验证最干净**：真值 q 可从会话算；但没有普通车位占用 |
| ACN-Data（Caltech/PowerFlex，注册免费，有 API） | 美国多站点 | 长期，**会话级** | 单次充电会话 | 同上，站点多、量大，适合验证反演 |
| ElaadNL / 丹麦（5534 个住宅充电桩，2022–2023） | 荷兰/丹麦 | 会话级 | 充电会话 | 补充外部有效性，场景与国内差异大 |
| SFpark（旧金山路侧地磁） | 美国，路侧车位 | 2011–2013，分钟级 | 车位占用（**无充电**） | 只能验证"占用车时/到达估计"，给不了 q |
| 上海临港"停车充电综合数据服务" | 上海，商业数据产品 | 聚合文件 | 车位总数/空闲数/使用率 + 充电电量/次数/时长 | 需付费申请，且疑似聚合非明细，不建议指望 |
| 广州"停车场点位数据"（网盘分享） | 广州 | 静态 | 点位 + 车位数 | 只能当底图，不能做识别 |

**怎么用（不必重新收数据也能推进）**：

1. **C 的验证**：用 4TU 或 ACN 的会话数据做闭环——从会话算真值 q，只把"充电位占用曲线"喂给反演，看能否圈回 q；
2. **B 的验证**：用 UrbanEV（深圳）做"占用 × 电量"的界——占用高、电量低就是占位不充电的直接证据，正好演示 B 的浪费率下界；
3. **广州经验案例**：仍用你手上那 1 个月占用数据做 ETP，q 用 UrbanEV 外部校准 + 区间敏感性，**写成区间而不是点估计**；
4. 想要"同场车位 + 充电桩"的真相，公开数据没有，只能找运营方或买商业数据。

**注意**：以上字段按各数据集的公开说明整理，**本轮未逐一下载验证**；UrbanEV 为小时级，估不了分钟级停留分布，停留分布要用 4TU/ACN 的会话数据校准。


## 修正（2026-10-29）：不需要五样，自己采一样就够

上面的五项是"有运营方配合"时的理想版，**自己采不现实**。实际只需要一个数据流：

**一个场，每 5–10 分钟，两个计数**：

1. 停车场当前占用车位数（或剩余车位数）；
2. 充电枪当前"空闲/充电中/故障"数（能到单枪更好，只能到站级总数也行）。

外加静态信息（现场/页面就有）：车位数、充电枪数、功率、价格、场地类型。

**来源（广州/广东，公开平台）**：

- 充电侧：**粤易充**（广东省统一充电服务平台，App/小程序，显示场站实时桩状态）；
- 停车侧：**广州泊车**（广州市停车平台，显示停车场余位）；
- 优先挑"两个平台都能查到的同一个场"，这样一次抓两行就够。

**为什么两个计数就够**：

- 占用车位数 → 到达量、停留时长（C 的输入）；
- 充电枪占用数 → 充电需求、占位不充电（B 的界）；
- 充电中数量的"上升沿"个数 ≈ 充电会话数 n_s（同时进出会低估，用换手率修正）——B 的公式要的就是它；
- 停留分布用公开会话数据（4TU/ACN）校准，或从本地占用曲线反推。

**工作量**：采集脚本 2–3 天，挂 4–6 周（覆盖工作日+周末+至少一个节假日），分析 2 周。不需要任何人给数据。

**合规**：低频（5–10 分钟）、只存计数不存个人信息、遵守平台条款和学校要求；接口不稳就退到半自动。

**退路（从好到差）**：

| 能拿到的 | 论文形态 |
|---|---|
| 余位 + 充电枪状态 | 完整 B+C，单场案例 |
| 只有充电枪状态 | B 收窄，C 只做充电侧 |
| 只有余位 | 只做 B 的宽界（d_min/d_max） |
| 两个都拿不到 | 换场/换城市；或用公开数据集做方法论文 |

**论文形态要改口**：原稿的 638 个场是学姐的数据；新论文做一个场的案例研究 + 方法贡献（B+C + 占位不充电），在方法/交通类期刊完全站得住，不需要大样本。

## 你只需要记住的五件事

1. 我们不是猜 q，是给 q 一个**区间**。
2. 区间靠**总账**（车时、充电次数）算，不靠分布假设。
3. 再做一次**模型反演**，跟区间对一对。
4. 对不上，就只报区间，并写"数据不足、不可识别"。
5. 最后把 q 的不确定性带进拐点，拐点就从点变成**区间**。
