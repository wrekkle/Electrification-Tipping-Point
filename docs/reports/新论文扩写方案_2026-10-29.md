## 6. humanize 自检

新增英文段落在写入后按 humanizer 24 条特征清单自查一遍，下表是本次实际处理的模式：

| 特征 | 处理 |
|---|---|
| 破折号过密（原稿大量用 em dash） | 新增段落一律不用破折号，改用逗号、分号或断句 |
| 三项排比 | 不凑三件套；三类需求、三条规则是模型本身的数量，不改 |
| AI 高频词（crucial、pivotal、showcase、delve、underscore） | 全删；robust 只作技术词 robustness 出现 |
| 负向对偶（not only… but also） | 未用 |
| 空泛归因（recent studies have shown） | 全部落到具体作者与年份 |
| 意义拔高（testament、pivotal role） | 未用；讨论段直接写条件与失败模式 |
| 同义换词（elegant variation） | 固定用 rule、design、configuration，不换词不换义 |
| 内联加粗小标题式列表 | 正文不用列表，只有图表占位段落 |
| 过度对冲 | 只保留证据要求的不确定性（如 confidence set 的渐近条件） |
| 通顺模板句（It is worth noting that） | 未用；改为直接陈述 |

改写示例（初稿→定稿）：
初稿："This is a crucial extension that enhances the model—highlighting, underscoring, and showcasing the importance of admission rules."
定稿："The rule is now a decision variable, so the comparison between partial and full installation no longer mixes a capacity change with a change in who may enter."
理由：删 crucial/enhances/showcase（宣传词）、删破折号与三连 -ing（表层分析）、把"重要性"换成可检验的机制陈述。

技能本身也声明：不保证通过任何 AI 检测器，只减少可识别的模板痕迹。本方案按同一口径使用，不宣称"去 AI 味"已被外部检测验证。
