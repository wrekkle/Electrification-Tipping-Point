# 文档写法

类型: 规范
状态: 生效
负责人: tho25
日期: 2026-10-29

写 docs/、paper/、literature/ 下的说明和报告前读这一份。计划写承诺，报告写证据，说明写怎么用。

## 总则

结论先行：第一段写清现在在哪、下一步做什么。时间写绝对日期（2026-10-29），不写"上周"。
一句话能说清就不写第二句；表格只在真有多列信息时用。

## 文本控制与归档

提示词直接在对话交付，不默认保存成 Markdown。下级 Agent 在原对话给出简短结论和证据路径，测试日志、配置、原始数据及机器结果保留在任务目录；不为每个 Agent 另写一份人读报告。

同一阶段由验收者在既有综合报告追加简短结果，保留旧证据与修订日期，集中更新 PROGRESS/TODO；确有新研究阶段或独立长篇论证才另建报告。任务和完成标准仍只记 TODO。

过时提示词与阶段交付归入 `docs/reports/archive/<日期-阶段>/`，提示词标记封存；移动后修复真实链接，保留历史断言及证据。归档说明写在 `docs/README.md`，不为归档再建一份说明或新索引。归档材料不作当前执行指令。

## 文件头与状态行

管理文档前 12 行内要有 `状态: 生效`（冒号半角），值只用五个：草案、生效、阻塞、已完成、已封存。
文件头四项：类型、状态、负责人、日期；类型写说明/规范/登记处/进度/报告/适配说明。

## 字段

- 计划：目标、不做什么、步骤、怎么算完成、风险与回退、尚未定的。
- 报告：结论、做了什么、证据、影响、没做完的、下一步。
- 章节条目（SECTIONS.md）：目的、文件、阶段、目标字数、证据缺口、下一步。
- 文献笔记（literature/notes）：出处、问题、方法、可复用点、局限、与本项目的关系、证据位置。

## 引用与命名

路径写在反引号里；只有真实存在的文件才写 markdown 链接；路径含空格时把链接目标放在尖括号里（Markdown 语法要求）。
报告命名 `docs/reports/YYYY-MM-DD-主题.md`；笔记 `literature/notes/<编号>-<短名>.md`。
不用"最终版""新版""最新"这类名字，版本关系用日期和修订记录说清。

## 用词

简洁、朴实、说人话。不造词；专有名词直接用通用说法。不用含糊指代（"本机""这边"），写具体路径或角色。
比喻只在解释陌生概念时用，且同一段写明它对应的实际东西。

## 长度

管理文档按档位管（300 / 1000 / 3200 / 6800 / 8000），口径是 LF 归一化后的 Unicode 字符数，含空格与标点。
当前登记见 [repo-discipline.json](../../repo-discipline.json) 的 `paths`；新文件从 300 档起，升档要登记。
不按档位管的有：论文正文、文献原文、历史记录、机器生成索引与报告、迁移与校验记录——它们照样在报告里显示长度。

## 两份统计不要混

管理文档看字符数；论文创作看汉字数、英文词数、字符数三个指标，口径写在
`repo-discipline.json` 的 `paper.count_rules`。稿件字数只由 `scripts/paper_stats.py` 算，
不抄 Word 的缓存字数，也不抄报告里的旧数字。
