参考项目 `C:\Users\tho25\WorkBuddy\neoAGu`（只读，未修改）是多人多机的量化研究仓库。下面说明
本论文项目采用了什么、改了什么、明确没要什么。

## 采用的机制

| neoAGu 的做法 | 本项目的落地 |
|---|---|
| 仓库只有一份主规则文件，别处文档不算规则 | `AGENTS.md` 唯一规则，冲突以它为准 |
| 目录归属表（什么放哪、什么时候读） | `AGENTS.md` 与 `docs/README.md` 的两张表 |
| 必读清单 + 合计字节上限 | `repo-discipline.json` 的 `required_reads` 与 `max_required_bytes` |
| 文档字符档位制（默认 300，按文件登记升档） | 沿用 300/1000/3200/6800/8000 五档，逐文件登记 |
| 字符口径按 LF 归一化 | 明确写成同一条口径：含空格与标点，换行计 1 字符，CRLF 与 LF 同值 |
| 待办只写一处、分三段、做完不删 | `docs/TODO.md`：还没做 / 未解决 / 已完成 |
| 状态词限定与固定写法 | 五个状态词，`状态: 值`，冒号半角，前 12 行内 |
| 只读检查脚本 + 自测 | `scripts/check_docs.py` 带 `--selftest`，另有 `paper_stats.py`、`lit_index.py` |
| 生成物必须有来源标记 | `docs/reports/` 与索引第一屏必须有"生成命令:" |
| 链接与长行检查、报告默认不落盘 | 全部保留；写文件要显式 `--out` / `--write` |

## 按论文项目调整的

- 档位值按实测重配：`AGENTS.md` 3200、`README.md` 3200、`docs/README.md`/`PROGRESS.md` 1000、
  `docs/methods/*` 与 `SECTIONS.md` 3200；默认 300 只留给未登记的新文件。理由：中文管理文档信息密度低，
  机械套 300 只会逼人拆碎文件。
- 长度统计拆成两套：管理文档用"LF 归一化字符数"；论文创作另算汉字数、英文词数、字符数，另加公式、图、表、
  参考文献条目计数。论文正文、文献原文、历史记录、机器生成物不套管理档位。
- 增加文献索引层：P01–P35 与 M01–M05 合成一份 `literature/index.json` 与 `literature/INDEX.md`，
  校验 PDF 存在性、文件头、字节数、SHA-256、编号连续、重复项，并把下载状态与阅读状态分成两个字段。
- 增加稿件层：`paper/SECTIONS.md` 记章节目的、阶段、证据缺口、下一步；字数块由 `paper_stats.py` 写，
  检查时核对是否过期。
- 历史记录不套档位也不许改：`research/`、`plan/`、`metadata/` 只读，与现状不符时写进新报告并在 TODO 登记差异。
- 去掉协作基础设施：无机器代号、无分支制度、无锁、无审批、无提交纪律——本项目一台机器、单人、无协作者，
  照搬只会增加空转。git 是否启用仍未定（见 TODO 的 U5）。

## 明确没要的

- `repo-discipline.json` 里的 `repeat_terms`、`rules_files` 多真源冲突检查：本项目只有一个规则文件。
- 决策记录 `DECISIONS.md`：规模不够，"为什么这么定"写在报告与 TODO 里即可。
- 隔离目录与分支回收脚本：没有跨机产物。
- 全局 git 钩子：不安装任何会改变用户既有设置的钩子。

## 参考项目里值得学但本轮没做的

- 每条规则配一个可执行检查（本项目的规则已尽量配检查，但"不许改写研究结论"仍靠人）。
- 清理与回收脚本（本项目暂无可清理的中间产物）。
